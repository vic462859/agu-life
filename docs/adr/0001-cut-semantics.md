# ADR 0001 · 「一刀割在最低点」的语义与代价

- 状态：已采纳（C1.4–C1.7）
- 日期：2026-11-21
- 相关：`src/core/engine/events.ts`、`scripts/balance-cut.mjs`、`tests/cut-semantics.test.ts`

## 背景

特殊年份事件里有一步 `cut`（文案「一刀割在最低点」）。原实现只做：

```ts
s.asset *= 0.9
return toOutcome(c, advance(c, q, Q.length))
```

**仓位没有清零**——玩家「卖了」，但下一季仍继续持仓吃涨跌。这是从单文件原版继承下来的语义矛盾。

## 为什么会拉扯

修成「割了就清仓」看起来是一行改动，实测却动了平衡：割完那一季正好是空仓，**躲过一次下跌**，而代价只有 −10%。于是「割」从惩罚变成了**免费期权**，且被复利放大。

量化（200 局/格，seed 1000–1199，固定策略）：

| 仓位 | legacy 平均倍数 | 清仓(代价 −10%) | 偏差 |
|---|---|---|---|
| 0.5 | 1.57× | 1.73× | +9.82% |
| 1.0 | 3.48× | 4.23× | **+21.74%** |

阈值（当轮设定）：倍数 ±15%、爆仓率 ±5pp。满仓档直接超阈值 ⇒ **不落地**。

## 决策过程（三次推翻）

1. **先扫参数**：把惩罚从 10% 扫到 40%。偏差随代价严格单调线性（满仓 ≈ −1.35%/pp、半仓 ≈ −1.22%/pp）。
2. **发现扫不出解**：满仓过零 ≈26.1%、半仓 ≈18.0%，两条 ±5% 区间在 22.2%–22.3% 擦肩而过。根因不在取值、在模型——**代价是常数，而"空仓期权价值"与仓位成正比**。
3. **改建模**：`loss = clamp(0.10 + 0.17·pos, 0.10, 0.35)`，由两条过零点插值得到。两档回到 −1.25% / −0.55%。
4. **杠杆暴露新缺口**：满仓+杠杆档仍有 +10.60%（杠杆把期权价值又放大 1.5 倍，而公式里只有 pos）。
5. **再加一项**：`loss = clamp(0.10 + 0.17·pos + c·lev, 0.10, 0.40)`，扫 c ∈ {0.04,0.06,0.08,0.10}，效应近零在 c ≈ 0.07。

## 决定

```ts
CUT_LOSS_BASE = 0.10   // 基准代价
CUT_LOSS_SLOPE = 0.17  // 每单位仓位增加
CUT_LOSS_LEV = 0.06    // 杠杆项（近零点 ≈0.07，取 0.06 以求稳）
CUT_LOSS_MIN = 0.10
CUT_LOSS_MAX = 0.40
```

- 默认口径 `liquidate`：清仓（`pos = 0`）+ 按上式扣代价；空仓时「这一刀没割到你」，不扣钱。
- `legacy` 保留作对照与回归，不再默认。
- 事件选项文案**不得出现具体数字**（原本写死「按 −10% 结算」，一旦与实际不符就是在选之前骗玩家）。现文案：「当场清仓，仓位越重、杠杆越高，这一刀越疼」。

## 后果

- 三组策略相对 legacy：满仓 −1.25%、半仓 −0.55%、满仓+杠杆 +1.51%，爆仓率三组均 Δ0.00pp。
- 取舍：**语义正确性换来了三个常数**。好处是「割」不再是免费期权；代价是模型多两个旋钮，未来调整平衡必须同时重跑三组策略。
- 记账口径：那一季在 `H` 记 `pos=0 / pnl=0 / isChg=0`（已清仓、没交易）。

## 方法论（本项目通用）

改任何影响经济/概率的代码，必须三件套：

1. **固定 seed 的批量对局**：≥200 局、多策略，**必须包含一套能爆仓的策略**（否则爆仓率恒 0，该维度没有鉴别力）。
2. **明确阈值**：倍数漂移 ±5%、爆仓率 ±2pp。
3. **超阈值就停手**：把表原样交回决策者，**不许自己继续调参把数字磨进阈值**。

选值时取 **|Δ| 最小者**（同分取更小参数），而不是「刚好过线的最小改动」——后者余量可能是 0.46pp，靠的是运气不是设计。
