# 微信小程序：3 步预览清单 + 上线资质

> 适用范围：本项目的 `build:mp-weixin` 产物（`dist/build/mp-weixin`）。
> 结论先说：**构建通过 ≠ 真机通过**。下面第 1~3 步是"看得到界面"的最小路径，
> 真机行为（音频、存储、字体、机型差异）一律未验证，见最后一节。

## 〇、先确认你的 AppID 是「小程序」不是「小游戏」

微信后台的**测试号**有两个互不通用的入口：**小程序测试号** 与 **小游戏测试号**。本项目产物是 **小程序**（`app.json` + `pages/*.wxml`，`compileType: "miniprogram"`），只能配**小程序测试号**的 AppID。

**实测证据（2026-11-21，本机微信开发者工具 2.01.2510290）**：把某个小游戏测试号的 AppID 写进 `project.config.json` 后执行 `cli preview`，工具按小游戏加载并报：

```
Error: game.json: 未找到 game.json 文件，或者文件读取失败 (code 10)
```

只要看到 `game.json` 相关报错，就是 AppID 类型不对 —— 换小程序测试号的 AppID，不要试图补一个 `game.json`（小游戏是 Canvas 渲染，本项目整套 UI 依赖 WXML/WXSS，不是补文件能解决的）。

拿到正确的 AppID 后，一条命令出预览二维码：

```bash
node scripts/mp-preview.mjs wx<16位hex>
# 产物：docs/shots/mp-preview-qr.png（手机扫码即可预览）
# 已存在产物时不会重建；加 --build 强制重建
```

## 一、预览三步

```bash
cd agu-life
npm run build:mp-weixin        # 产物：dist/build/mp-weixin（含 app.json / project.config.json）
```

### 第 1 步：装微信开发者工具
下载并安装「微信开发者工具 · 稳定版」（官方页：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html ），
装完用微信扫码登录。安装与登录都必须由人来做，脚本无法代劳。

### 第 2 步：准备 AppID（没有就用测试号）
本项目的 `src/manifest.json` 里 `mp-weixin.appid` 现在是**空字符串**：
```json
"mp-weixin": { "appid": "", "setting": { "urlCheck": false } }
```
两条路，二选一：

- **测试号（最快）**：开发者工具新建/导入项目时，AppID 处点「测试号」由工具分配。测试号能做预览，
  但**不能上传发布**，也开不了需要真实 AppID 的能力。
- **正式 AppID**：到 https://mp.weixin.qq.com 注册小程序拿到 AppID，填进 `src/manifest.json` 的
  `mp-weixin.appid`，再 `npm run build:mp-weixin` 重新构建。

> 不要直接用工具里"游客模式"去跑正式发布流程——它跟测试号一样，上传会被挡。

### 第 3 步：导入 dist/build/mp-weixin
开发者工具 → 导入项目：
- 目录：`<项目根>/dist/build/mp-weixin`（**不是** `src`，也不是项目根）
- AppID：上一步拿到的测试号或正式 AppID
- 后端服务：本项目是纯前端单机，选「不使用云服务」

导入后：模拟器里应出现「1984 · 你 18 岁 / 你从哪儿来」三个出身卡片。
要点一遍「厂里子弟」看能不能进主流程、能不能存档（存档在 `src/platform/storage.ts`）。

> 改动 `src/**` 之后必须重新 `npm run build:mp-weixin`，开发者工具不会自己编 TS。

## 二、上线所需资质（全部由人/公司办，代码侧无法替代）

| 事项 | 谁办 | 说明 |
| --- | --- | --- |
| 小程序主体认证 | 账号主体 | 个人主体可注册，但**可选服务类目受限**；企业主体需对公打款或法人验证，认证费 300 元/年（官方口径，以微信后台为准） |
| 软件著作权（软著） | 主体 | 应用商店/部分类目与渠道会要；正常受理约 30 个工作日，加急另议 |
| ICP 备案 | 主体 | 小程序自 2023 年起需完成备案才能上架；**官方通常口径 7–20 个工作日**（看接入商审核+管局），备案期间不能提审 |
| 类目资质 | 主体 | 若选"金融/证券"相关类目，会要求金融牌照类资质——本产品是模拟游戏，**应选游戏/文娱类目，不要选金融类目**，否则资质根本办不下来 |
| 版号（企业主体） | 主体 | 含付费或需版号的游戏类目，企业主体要提供游戏版号；个人主体无法申请版号，因此**个人主体只能做不含付费、走文娱类目的免费版本** |
| 隐私政策 + 用户信息保护指引 | 主体 | 后台「用户隐私保护指引」必须填；本项目只做本地存档，声明里要写清"不收集个人信息" |

时序建议：**先备案（7–20 工作日）→ 同步办软著 → 认证 → 提审**。备案是最长的一环，先起。

## 三、合规表述（必须出现在用户看得到的地方）

- 页面/关于页固定一句：**「本产品为模拟游戏，不构成任何投资建议。」**
  （`src/manifest.json` 的 `description` 已经带了这句，但用户看不到 manifest，必须有 UI 落点。）
- 不用"荐股""收益""稳赚""内幕"这类词描述玩法；行情数字标注为「历史数据回放 / 模拟数据」。
- 涉及真实个股名称时，建议改成虚构代码或明确写"以下均为虚构示例"。
- 充值/广告接入前再补一条「虚拟物品仅用于游戏内体验」。

## 四、已知未验证项（别当成已通过）

1. **微信开发者工具没装过**，导入流程是按官方文档写的，未实测。
2. **真机未跑过**：音频（`src/platform/audio.ts`）、本地存储（`src/platform/storage.ts`）在真机上的表现未知。
3. **AppID 为空**，`urlCheck:false` 是开发期配置，正式版要在后台配合法域名（本项目无请求，理论上不需要，但未验证）。
4. **包体积未核对**：`dist/build/mp-weixin` 目前只有 `app.js`/`common/vendor.js`/页面 js，未做分包，主包 2MB 限制未实测（当前体积远小于上限）。
5. **字体/图标**：小程序不支持 `@font-face` 外链字体，本项目用的是系统字体，未在 iOS/Android 上对过字重。
6. **审核风险未知**：模拟炒股类内容可能被要求补充资质或判定为"金融信息"，以审核结果为准。
